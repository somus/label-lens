# Reference: `labellens.config.json`

Generated by `labellens init` next to your JSONL. Edit by hand to tune labels, guidelines, or display.

The file ships a `$schema` URL pointing at [`schema/labellens.config.schema.json`](https://raw.githubusercontent.com/somus/label-lens/main/schema/labellens.config.schema.json). VS Code / Cursor / Helix pull descriptions + autocomplete from that URL automatically — see [how-to: edit the config](../how-to/edit-config.md) for editor-specific setup, schema pinning, and shell-side validation. LabelLens validates the file against the same schema at startup; mismatches exit with code 2 and a path/field error.

## Top-level shape

```jsonc
{
  "$schema": "https://raw.githubusercontent.com/somus/label-lens/main/schema/labellens.config.schema.json",
  "task": "classification" | "boundary",
  "labels": ["food", "travel", { "name": "salary", "key": "s", "color": "green" }],
  "guidelines": "Optional path or inline markdown.",
  "input":  { "path": "data.jsonl", "format": "jsonl", "fields": { "text": "text", "prediction": "prediction" } },
  "output": { "path": "reviewed.jsonl", "format": "jsonl" },
  "boundary": { "documentField": "document_id", "contextLines": 3 },
  "classification": { "previewLines": 2 },
  "display": { "color": "auto", "banding": "auto", "theme": "auto", "labelChip": "configured", "sidebar": "auto" },
  "navigation": { "smartNext": false },
  "assistant": { "enabled": false, "provider": "anthropic", "model": "claude-sonnet-4-5", "apiKeyEnvVar": "ANTHROPIC_API_KEY", "privacyAcknowledged": true },
  "signals": { "lowConfidenceThreshold": 0.5, "enable": ["lowConfidence", "disagreement", "duplicate", "flagged"] },
  "notes":   { "presets": ["needs-domain-help", "ambiguous-text"] },
  "keys":    { "record.accept": "y" }
}
```

## `task` (required)

For examples and task-selection guidance, see [Review task types](../explanation/task-types.md).

| Value | Meaning |
|---|---|
| `classification` | One label per record. |
| `boundary` | Segmentation over a document — labels mark entry boundaries (`ENTRY_START`, `CONTINUATION`, etc.). |

## `labels` (required)

`string[] | LabelConfigEntry[]`. Strings are sugar for `{ name: <string> }`.

| Field | Type | Meaning |
|---|---|---|
| `name` | string | The label value stored on `reviews.final_label`. Used in queries (`by-label:food`) and exports verbatim. |
| `key` | string (1 char) | Per-label keyboard accelerator. `[k]` chip on the rail; pressing `k` commits the relabel. Validated at startup — can't collide with built-in bindings (`a`, `r`, `x`, `s`, `m`, `n`, `i`, `j`, `k`, `u`, `t`, `q`, `:`, `?`, digits, chord starters). |
| `color` | string | Reserved for label tinting in the chip rail. Not yet honoured. |
| `glyph` | string | Reserved for boundary-task per-label glyphs (V1). |

## `guidelines`

Either inline markdown or a path to a markdown file. Rendered in the guidelines viewer (`g g`).

```jsonc
"guidelines": "## Rules\n- Always tag X as Y\n- ..."
// or
"guidelines": "./docs/labeling-guidelines.md"
```

## `input` (required)

| Field | Type | Meaning |
|---|---|---|
| `path` | string | Source JSONL. Resolved relative to the config file. |
| `format` | `"jsonl"` | Only `jsonl` is supported in MVP. |
| `fields` | `FieldMap` | Maps logical fields to actual JSONL keys (see below). |

### `FieldMap`

| Field | Required | Default JSONL key | Meaning |
|---|---|---|---|
| `text` | yes | `text` | Candidate text the reviewer sees. |
| `prediction` | no | `prediction` | Model's predicted label. |
| `confidence` | no | `confidence` | Float 0..1. Drives `low-confidence` queue. |
| `source` | no | `source` | Provenance tag, e.g. `llm:gpt-4`. Drives `by-source` queue. |
| `context_before` | no | `context_before` | String shown above the candidate row. |
| `context_after` | no | `context_after` | String shown below. |
| `id` | no | `id` | Stable record identifier. Falls back to content hash (ADR 0001). |

`labellens init` infers these by sampling the JSONL — see [`src/config/inference.ts`](../../src/config/inference.ts) for the candidate keys per field.

### Multi-prediction records

A record may carry multiple predictions via a `predictions[]` array:

```jsonl
{"text": "...", "predictions": [{"label": "food", "confidence": 0.7, "source": "llm:gpt-4"}, {"label": "shopping", "confidence": 0.6, "source": "regex"}], ...}
```

Each prediction lands as its own row in the `predictions` table. The highest-confidence row becomes the **primary prediction**. The `disagreements` queue surfaces records whose `predictions[]` carry ≥ 2 distinct labels.

## `output`

| Field | Type | Meaning |
|---|---|---|
| `path` | string | Destination for `labellens export`. |
| `format` | `"jsonl"` \| `"csv"` | Default format if `labellens export` is invoked without a positional argument. |
| `includeRejected` | boolean | Default for `--include-rejected`. CLI flag still wins when present. |
| `includeSkipped` | boolean | Default for `--include-skipped`. Emits skipped records with `label: null`. |
| `csvMultiLabelSeparator` | string | Joiner for multi-label arrays in CSV exports. Default `;`. |
| `fieldOverrides` | object | Per-column renames on export. Recognized keys: `id`, `text`, `label`, `reviewed_at`, `document_id`. |

CLI flags (`--include-rejected`, `--include-skipped`) override these defaults. When neither is set the default is `false`.

## `boundary` (boundary task only)

| Field | Default | Meaning |
|---|---|---|
| `documentField` | `"document_id"` | JSONL field name that groups records into documents. |
| `contextLines` | `3` | Number of neighbouring lines shown above and below the focused row in the subject pane. |

## `classification` (classification task only)

| Field | Default | Meaning |
|---|---|---|
| `previewLines` | `2` | Queue-sibling rows shown above/below the focused record. Set `0` to hide. These render dimmer than boundary's semantic neighbours. |

## `display`

Terminal capability + theme are detected at startup. These overrides force a specific behaviour.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `color` | `auto` \| `truecolor` \| `256` \| `16` \| `mono` | `auto` | Force a capability level. `auto` reads `$COLORTERM` / `$TERM` / `$NO_COLOR`. |
| `banding` | `auto` \| `on` \| `off` | `auto` | Banded background per record. Forced off at 16 / mono. |
| `theme` | `auto` \| `light` \| `dark` | `auto` | Light/dark palette. `auto` probes terminal via OSC 11; falls back to `light` on timeout. |
| `candidatePin` | `0.05`..`0.95` | `0.4` | Viewport pin position (fraction of subject height). |
| `layout` | `auto` \| `stack` \| `split` | `auto` | Stack or split layout. Auto picks split at ≥ 160 cols. |
| `motion` | `auto` \| `on` \| `off` | `auto` | Fades, flashes, progress tweens. Forced off at 16 / mono. |
| `sidebar` | `auto` \| `on` \| `off` | `auto` | Right-column chrome. Auto shows at ≥ 120 cols on truecolor / 256. |
| `queuePreview` | `auto` \| `on` \| `off` | `auto` | Left-column upcoming-record rail. Auto shows at ≥ 200 cols when sidebar is also visible. |
| `labelChip` | `configured` \| `both` | `configured` | Chip rail format. `configured` → `[k]` when label has a key, else `[N]`. `both` → `[N/k]` when both apply. |

## `navigation`

| Field | Default | Meaning |
|---|---|---|
| `smartNext` | `false` | When true and the queue is `pending`, `j` / `k` walk a signal-weighted `smart-pending` cursor (low confidence + disagreement + flagged bubble up). `shift+j` / `shift+k` always navigate document order. |

## `assistant`

LLM assistant (PRD §10.5). Off by default.

| Field | Type | Meaning |
|---|---|---|
| `enabled` | boolean | When false, `i` opens the configure overlay; when true, fires `queryAssistant`. |
| `provider` | string | One of `anthropic`, `openai`, `google`, `groq`, `ollama`. |
| `model` | string | Provider-specific model id (e.g. `claude-sonnet-4-5`). |
| `apiKeyEnvVar` | string | Env var name to read the API key from at runtime (e.g. `ANTHROPIC_API_KEY`). The key itself is never persisted. |
| `ollamaUrl` | string | Base URL for the Ollama provider (e.g. `http://localhost:11434/v1`). |
| `privacyAcknowledged` | boolean | First remote call is blocked until this is true. Configure overlay flips it after the reviewer confirms the privacy notice. |
| `systemPromptAppend` | string | Extra instructions appended to the system prompt for every assistant query. Hashed into the cache key so edits invalidate stale entries automatically. |

Pass `--local-only` on the CLI to refuse remote providers regardless of config.

## `signals`

Tunes the prioritization-signal pass (PRD §10.4).

| Field | Default | Meaning |
|---|---|---|
| `lowConfidenceThreshold` | `0.5` | Confidence under which the `low_confidence` signal fires. Records with `primary_confidence < threshold` land in `by-issue:low_confidence`. |
| `enable` | all four | Subset of signals to compute. Values: `lowConfidence`, `disagreement`, `duplicate`, `flagged`. Disabled signals stop producing `issues` rows — their queues + chips disappear and `smart-pending` stops weighting them. |

## `notes`

| Field | Meaning |
|---|---|
| `presets` | Array of phrases. Surfaced in the note overlay; `alt+1`..`alt+9` appends the matching preset onto the in-progress note. Cap at 9. Blank entries are dropped. |

## `keys`

Per-command keybinding overrides. The key is a command name (see [keybindings](./keybindings.md) for the action vocabulary); the value is the new key.

```jsonc
"keys": {
  "record.accept": "y",
  "record.reject": "n"
}
```

Rules:

- Override key must be a single character.
- Override key cannot collide with another built-in binding (after applying all overrides) or with any configured `labels[].key`.
- Override key cannot already be claimed by another `keys` entry.
- Vacated keys (e.g. the original `a` for `record.accept`) become free to reuse — for a label key, or for another override in the same config.

Validation runs at startup; failures exit 2 with a list of conflicts.

## Validation

Config is loaded once at startup. Failures exit with code 2:

- `labellens: invalid <path>` followed by one line per JSON-Schema violation (TypeBox `Value.Errors`).
- `labellens: invalid config.labels[].key` — per-label key collides with a reserved binding or another label.
- `labellens: invalid config.keys` — override key conflicts or unknown command name.
- `labellens: --local-only set but assistant.provider is '<X>' (remote).` — flag/provider mismatch.
- `labellens: configured label set is missing values referenced by stored data.` — DB has rows tagged with labels not in `config.labels`. Either re-add the label or use `labellens migrate --rename old:new` to remap.
